# 控制与学习实现

## 数据链路

Lua 在游戏线程读取当前本地玩家的姿态、速度和输入，送入原生桥接。原生模块读取鼠标位移、产生世界空间目标方向，计算俯仰/滚转/偏航指令，再由本地玩家输入路径应用。相机和 GPU GUI 使用对应帧的数据。GUI 不额外绘制游戏已经提供的十字准星。

核心实现位于 `native/src/mouse_aim.cpp`、`full_model_runtime.h`、`model_control.h`、`model_serving.h`、`online_learning.h`。其他旧 runtime 头文件是保留的历史实现，不是当前入口。

## 响应模型与在线学习

每个轴使用一阶角速度响应近似，主要参数是操纵响应增益 K、响应时间 τ 和输入延迟。标准参数来自早期试飞拟合，未重建完整的空气动力学、轴间耦合、攻角或过载约束。

学习器按机型维护三个轴和四个速度区间。每区间评估 405 组增益/时间常数/延迟组合。48 个具有有效操纵变化的样本用于拟合，24 个后续样本用于独立验证；部署前还要求较长时间尺度的预测检查。候选和当前部署模型分离，候选重新验证不清空正在服务的参数。

验证通过后，参数逐渐进入控制。标准模型始终可用，没有学到新参数不意味着模型控制停止。手动操纵、刹车或特定环境条件会暂停学习；手动轴优先，数据无效或过旧时保留控制回退。

数据按机型独立保存在当前进程内，最多 64 个机型槽位。退出游戏清空。速度分区边界为 270/480/710m/s，新分区没有通过验证的参数时会渐变回标准模型。目前跨区衔接仍是已知优化方向。

**模型增益低于 1 表示预测飞机对单位操纵响应较弱，不表示控制器一定降低操纵量。**控制输出还受到目标误差、角速度、延迟预测、阻尼与限幅的共同影响。

## F4 两档

两档共用上述学习结果，切换本身不清空状态。

| 约束 | CLASSIC 2.0 | AGILE 2.1 |
|---|---|---|
| 自动俯仰幅度 | ±0.85 | 追赶时最高 ±1.00 |
| 自动滚转幅度 | ±1.00 | ±1.00 |
| 自动偏航幅度 | ±0.70 | 追赶时最高 ±0.85 |
| 角速度余量 | 模型能力的85% | 追赶时放宽到95% |
| 终端角速度惩罚系数 | 标准模型2.0，学习参数充分引入后1.5 | 远目标追赶时最低1.25，制动区恢复保守值 |

AGILE 的名义角速度约束可从俯仰45到60、滚转70～140到87.5～175、偏航7到9度/秒渐变。实际计划约束还应用学习响应倍率并取模型可达到能力的较小值，不能当成飞机必然达到的角速度。

是否进入积极追赶由当前误差、延迟后的预测误差和制动距离余量共同决定。F4 切换用约0.35秒混合两档计划及权限；实际操纵量继续限速。两档是控制策略，不是游戏气动参数修改，也不保证贴着真实飞行包线飞行。

## 采集与诊断

每段新飞行最多约15分钟，整个进程最多720000行。达到记录上限不会停止控制或学习。当前 CSV 为100列，`assist_profile=6`。

- `selected_control_mode`：0经典、1积极；`control_mode_blend`：实际过渡进度。
- `primary_weight`：模型主控制权重；`primary_delta` 为相对于旧基础指令的差，不是控制覆盖率。
- `learn_weight`：部署参数混合；`candidate_weight`：候选混合。
- `model_source`：0标准、1学习、2参数过渡、-1手动或回退。
- `pursuit`、`effective_damping`、`plan_input_limit`、`primary_ratecap`：积极追赶状态与计划约束，不是物理包线测量。

换机首帧的统计计数可能滞后，应过滤无效/切换帧，并核对带机型标签的 `MODEL_PARAMETERS_DEPLOYED` 日志。不同任务、速度和机型的自然飞行不能直接当成同条件 A/B 测试。
