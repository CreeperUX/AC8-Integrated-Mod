# 发布前代码审核（2026-10-04）

## 范围与结论

审核基于 GUI/三模式合流提交 ad75e0a，在 audit/release-hardening 分支进行。包括安装、Steam入口、GUI后台任务、三种范围隔离、部署/退出清理、包完整性，以及稳定飞控/Lua的既有回归。没有合回2.4实验控制，没有发布或替换当前默认安装。

结论：下列确认问题已修复并通过本地回归，可以继续作为实机候选；不能据此承诺所有电脑、任务和显示环境无问题。旧GUI-Test1/Test2及已生成的旧ZIP不会自动得到这些修复。

## 修复项目

| 优先级 | 问题 | 修复与证据 |
|---|---|---|
| P1 | Get-FileHash在Steam或独立runspace不可用，而包检查采用另一实现，导致检查通过后启动或清理失败 | PowerShell-Compat统一流式.NET SHA256；从PSHOME绝对路径加载内置模块；所有产品脚本改用Get-AC8FileHash；CMD固定系统Windows PowerShell。标准向量、方括号路径、缺失命令/空模块路径/关闭自动加载通过 |
| P1 | 多个启动/清理过程可能同时写会话记录或处理同一游戏目录 | 按规范化游戏目录使用命名互斥；覆盖会话入口、部署生命周期、清理与恢复。不同线程拒绝、同线程嵌套清理和释放重入通过 |
| P1 | 链接目录可被部署，但后续安全清理拒绝链接，留下残留 | 部署前和GUI环境检查提前拒绝此目录结构；测试确认拒绝发生在写入游戏之前 |
| P2 | 完整Session入口没有只读预检，简单透传参数可能先触发旧会话清理 | Run-Console/Start-ModSession在清理/恢复前分流；CheckOnly仅允许Session，不写诊断文件；残留会话保持字节不变 |
| P2 | manifest只比较数量，同数量重复项可能漏校验另一个文件 | 规范化路径去重，重复清单项直接拒绝，损坏payload与缺失门控仍拒绝 |
| P2 | 会话JSON的Results路径异常时，诊断归档可能写到包外 | 清理后的可选诊断限定本包sessions目录，异常时保留已验证备份并报告跳过；不会阻断已完成清理 |
| P2 | Steam配置扫描把两个反斜杠当作单字符，带大括号路径解析可能提前结束；任意旧账号的匹配配置也可能被误认 | 修正转义字符；优先当前ActiveUser，无法识别且多账号时拒绝假通过。带引号/方括号/未配对大括号、错误账号、多账号歧义均测试 |
| P2 | 隐藏GUI进程在窗口创建前报错，可能没有可见提示 | 顶层启动异常写诊断并显示错误，返回非零状态；后台初始化错误结构化返回。无窗口测试确认缺文件仍留诊断 |

## 验证

- 原生：模式切换、三轴控制与独立学习、限幅/数据过期回退、记录窗口、M15观察入口全部通过。原生源码未改，最终候选复用已验证的2.3.2飞控DLL。
- Lua：三模式字段隔离（guidance32字段、full375字段、none不部署）、幂等/恢复、任务重新初始化、模型模块加载门控、检查点恢复和M15元数据入口通过。
- PowerShell：HostIsolation、SteamBridge、GUI（17场景）、Discovery（9场景）、Cleanup（21场景）、InstallUX（11场景）、Feature/Package/Setup/主题测试通过。
- GUI：真实WPF按钮、异步dispatcher、忙碌状态、错误显示与隐藏启动失败验证通过；使用隔离fixture，不启动游戏或Steam。
- 打包：完整包及独立清理工具包含兼容依赖，重新生成FILES.sha256与ZIP校验。payload及飞控算法不因本审核更改。

其中模拟游戏EXE的测试仅替换假EXE哈希，真实包文件仍计算SHA256；不能当作真实游戏启动证明。历史残留测试只操作临时fixture。
