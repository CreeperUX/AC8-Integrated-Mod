# 过场后模组相机／HUD 不恢复：修复说明（v2.4.0）

[返回说明首页](../README.md) · [相机与过场](CAMERA-CONTEXT.md)

## 症状

在 v2.3.15-beta.1 及之前，进入某些过场时（例如 Mission005），或在按住 C 环视期间切入过场，可能出现以下情况，并且直到退出游戏都不恢复：
- 模组相机退回游戏原版相机；
- 圆环和 HUD 消失或停止更新；
- 体感上是"鼠标飞控失效，键盘正常"。

日志中会出现：

```text
native camera disabled: invalid live camera/aircraft data
```

## 原因

模组每帧接管相机前，会校验相机管理器、飞机根组件、坐标、FOV 和指令数值。旧版只要有一帧校验失败，就把相机接管永久停用。最终相机／HUD 快照也随之不再刷新，而 HUD 和部分输入路径依赖这份快照。

2.4.0 的诊断日志显示，过场切换帧上失败的是 **FOV** 一项：游戏在切换镜头时短暂给出了超出有效范围的视野角。

## 修复

1. **受保护重试：** 校验失败只暂停接管，最多每 500 ms 重试一次。每次重试仍要满足原有全部条件：
   - 匹配的相机和当前飞机；
   - 新鲜的姿态和指令；
   - 游戏在前台；
   - 不处于暂停、注视或过场。

   仍执行全部有效性检查；失败的那一帧不会写入相机内存。
2. **诊断：** 日志写明是哪一项校验失败，例如 `(...)(fov); retrying every 500ms`。恢复时记录 `native camera recovered after N rejected attempt(s)`；持续失败只记录一次。
3. **鼠标输入回退：** 最终相机快照缺失或过期时，使用游戏线程刚提供的新鲜姿态／视角快照，原有的时效、飞机身份、暂停和过场检查不变。默认的逐帧输入方式本身就不依赖该快照，这一条是额外保险。

## 验证

- **回归测试：** 新增回归测试 `cutscene_recovery_tests` 模拟"一帧无效数据后恢复"，旧实现在恢复这一步失败，新实现通过。测试同时覆盖持续无效、过场、暂停、注视、换机、失去前台和数据过期时不会误恢复。
- **实机验证：** 试飞中实际触发了一次（按住 C 环视、约 2 s 后进入过场）：校验因 FOV 被拒 4 次，过场结束后模组相机和 HUD 立即自动恢复。
