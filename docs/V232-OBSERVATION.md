# 2.3.2 任务专用飞机的数据入口修复

2.3.1 与 2.4.0 的任务 15 A-6E 记录均出现输入数据存在、状态数据为零、模型控制日志缺失的情况。旧桥接将机型、速度与可选采样的坐标、时间放在同一校验中，任意一项失败就静默返回。旧记录不足以判定究竟是哪一个字段被拒绝。

本版基于 2.3.1，不包含 2.4.0 的实验控制算法。Classic/Agile 控制律、限幅、阻尼、鼠标灵敏度、导弹模块均保持原样。

- 每个有效游戏帧独立更新机型、速度及环境信息；录像失败不再停止模型数据更新。过期数据仍触发原有回退保护。
- `BP_PlayerPlane_PP0013_a06e_ms15_C` 使用独立本地学习键 `2147483013`，从通用模型开始学习。这不是游戏原始 PlaneTypeID，也不与普通 A-6E 合并学习。日志同时保留实际读取的原始 ID。
- 其他机型接受精确、非负、可表示为有符号 32 位整数的 ID，移除没有类型依据的 100000 上限；拒绝小数、溢出和无效 ID。
- 录像错误每 10 秒重试，控制数据失败会明确记录 `DEGRADED`。未知刹车值暂停学习，但不阻止通用模型控制。
- 分析报告没有状态证据时，不再自动宣称预测控制已经介入。

正常从原来的启动入口进入任务即可，无新增按键。F4 切换 Classic/Agile，F8 开关鼠标飞控。

验证重点：`ControlObservation` 中的任务机型和原始 ID；`CONTROL_OBSERVATION status=1`；`MODEL_FULL data=1`、三轴 `primary` 上升及有效 `source`。`source=0` 表示通用模型正在控制，学习通过验证后才部署学习参数。

自动化验证覆盖机型回退、整数边界、录像失败隔离、三轴通用控制介入，以及原有控制器回归。实机任务是否改善仍须飞行日志确认；离线测试不能证明真实手感或保证不再出现其他问题。
